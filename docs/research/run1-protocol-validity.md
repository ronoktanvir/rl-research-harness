## The primary measure, helpers and judge are different mechanisms

The primary is the count of required facts both acquired through the audited read path and credited in the memo, divided by **all required-fact opportunities**, including episodes that never contact a helper. This denominator avoids rewarding selective success reporting. The funnel aggregates repeated disclosures to a per-episode/per-fact indicator; it is not a count of helper messages. Contact is an episode-level category-relevance flag applied to both required facts, not two independently verified fact-specific requests. See archived `heldout_funnel.py` 1–25, 62–70, 88–135.

Acquisition is an operational proxy. The v4 audit requires an observation uniquely matched to its tool-call ID, agreement between posting counters and post acknowledgements, the exact disclosing channel, and a read after the triggering post whose **posts payload** contains the fact value. It cannot establish strict arrival of the emitting message ID because the read format lacks that identity. Nor does arrival establish comprehension or correct downstream use. See archived `disclosure_audit_v4.py` 61–65, 176–255, 299–375.

The legacy credit predicate is deterministic. It finds an accepted value spelling and metric alias in the same sentence-like segment, then rejects a bounded list of nearby negators. It does not parse semantic relations; canonical value forms explicitly exclude unit-scale equivalence. `grade()` combines that predicate with a disclosure scan. See archived `extraction.py` 134–153, 182–240 and `reward.py` 235–269. Consequently, the spec's 166–167 statement that the credit stage “is judged” is inaccurate if it means the LLM judge: the source computes that credit first and preserves it.

The separate LLM judge scores memo quality from the brief, memo and precomputed coverage labels. It does not receive the ground-truth values, transcript or disclosure ledger as independent verification inputs, and its prompt explicitly takes credited figures as accurate. The evaluation uses the training path's **banded** composition, despite the generic judge module describing an unbanded default. Judge errors can drop results and therefore affect completion, but judge scores do not determine the credit predicate. See archived `judge.py` 1–27, 61–75, 99–130, 335–381 and `fit_loop.py` 337–345. In the inspected s11 files, 21 trained and 17 baseline rows record `gpt-5.5-2026-04-23` / `judge-v4` / `banded`; the remaining 363/367 rows have null judge fields, consistent with the no-judge path for zero credit. These are recorded producer identities, not independently attested provider responses.

The exact archived heldout driver constructs `RolloutEngine` without an LLM helper backend. The rollout forwards a backend only when supplied, the in-memory provisioner defaults to `None`, and `helper_turn()` then chooses `ScriptedHelperBackend`. See driver 394–401, rollout 754–763, memory provisioner 222–241 and helpers 205–249. The s11 records also omit helper-usage/fallback fields. This supports **scripted-helper routing in the declared evaluation implementation**, not an inference that a Claude helper ran merely because an LLM-helper module exists. No independent historical execution-custody evidence closes that last qualification. The helper and judge roles are separate in code; they are not independent scientific adjudicators of task truth.

## Adjudication and collection schema

The next module should accept a bounded frozen case packet, then produce a content-hashed receipt. Its minimum fields are:

- `caseId`, `caseKind` (`synthetic` or separately authorized `historical_sample`), versioned test intent, task-package/scorer/instrument hashes, and source artifact SHA256 plus exact record/event pointers. A current run label cannot substitute for identity.
- Explicit fact IDs with quantity, unit, metric, holder and relevant task meaning; ordered synthetic post/read/submit events with unique call/message IDs; memo text only inside the bounded local case artifact. Store references and digests in evidence receipts, not copied private historical traces.
- Separate expected labels for disclosure, attributable arrival, legacy text credit, metric/value/unit correctness, source attribution, assertion status, direction and task usefulness. Use `true | false | unknown | not_applicable` with explicit reason codes; no coercion of missing values to false or approval.
- Machine observations distinct from adjudicator annotations. Each annotation identifies reviewer, rubric version, evidence pointers and rationale. Two independently prepared annotations may agree or disagree; unresolved disagreement stays visible. An adjudication decision records why it resolves a specific disagreement, without a majority vote becoming truth.
- Raw cached judge-result identity, parsing status and disagreement with adjudication, if supplied. A structurally valid cached response never upgrades its own semantic accuracy.
- Summary by failure class and denominator, with exact included/excluded/unassessable case IDs. Preserve one training replicate for the s11 policy; the number of annotation cases is not replication count.

Optional later work is a stratified historical sample with policy/arm labels hidden from annotators, including credited positives and explicit negative/control examples. That would test semantic error on recorded behavior, but retrospective masking cannot create historical holdout blindness. An enriched error-discovery sample also cannot estimate a population error rate without a declared sampling design. New protected evaluation, matched training controls and independent training replications remain separate prospective requirements.
