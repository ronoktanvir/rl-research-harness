# Replay evidence archive: independent reviews

The reviewed import preserves the qualified local replay bundle as one immutable, unlinked observation and supports offline reuse without invoking the native worker. The independent import review found no material defect within its declared trusted-directory boundary. This document separates the 24 import regressions and saved qualification review from the annotation and scientific interpretation review below. ## Import and persistence boundary

Final CLI and shared-validator review found one material integrity defect: default UTF-8 decoding removed an initial byte-order mark, allowing a report's bytes to change while its decoded content still matched the receipt. The decoder now preserves the character, so derived-report comparison rejects it. A regression first reproduced the failure, then verified that both load and recovery reject while leaving the altered report and original receipt untouched. The focused suites passed 38 tests after correction. The same review confirmed redacted CLI summaries, deterministic archival timestamps, output overwrite refusal, ledger closure and cached validation without original-file reads.

The reviewed implementation is [replay-evidence.ts](../../src/integrations/coworker/replay-evidence.ts), with the pure bundle validator in [observed-replay-artifacts.ts](../../src/integrations/coworker/observed-replay-artifacts.ts). The independent suite, [coworker-replay-evidence-independent.test.ts](../../test/integrations/coworker-replay-evidence-independent.test.ts), passed **24 tests**. Its fixtures exercise real SQLite persistence and pure bundle recovery with a nonexistent Python executable; they make no native, provider, service or training calls.

The tests cover complete private evidence retention with a redacted summary; project and source identity; null run/action/job links; immutable retry identity; reopening and cached reuse after deleting the original artifact root; input snapshots before asynchronous work; accessor rejection; traversal, symlink and hard-link rejection; changed reports and receipts; expected request/execution/receipt digest mismatches; contradictory approval prose and source ownership after outer hashes are recomputed; incomplete and cancelled outcomes; bounded large context; atomic append failure; and concurrent identical imports preserving the first observation. Stored records with false authority, altered scope or inconsistent identities reject on reload.

**The filesystem contract requires operator-owned directories and stable ancestors during import.** Component and before/after identity checks detect links and ordinary replacement; they do not provide descriptor-relative protection against a malicious concurrent ancestor swap. Queued ingestion or an untrusted artifact writer needs a stronger isolated store boundary. Hash consistency also cannot authenticate a complete evidence chain rewritten by a trusted writer. The archive therefore retains `originStatus: operator_declared`, `sourceCustody: not_authenticated` and unassessed scientific/task outcomes.
