# Ledger, dispatch and capture review

Date: 2026-11-01, America/Los_Angeles. Independent agents reviewed implementations they did not author, added separate adversarial tests and verified corrections. The orchestrator reviewed capture/ledger integration and published the components as one coherent local controller slice.

## Material findings and corrections

| Finding | Consequence | Correction and regression |
|---|---|---|
| Schema initialization preceded version inspection | Opening an unsupported store could write before rejecting it | Inspect version/foreign-store identity before main schema writes |
| Exhausted unsettled bounds allowed discretionary work under a larger scope cap | Numeric residual reservation obscured unbounded remaining liability | Hold ordinary admission/claims in every overlapping scope until exposure is resolved; retain truthful charges without double counting |
| Stop blocked cleanup alongside ordinary work | An invalidated or stopped experiment could not be targeted for cancellation | Named cleanup admission generates a fixed original-target payload; configured operation/backend permission and fresh authority still apply |
| Cleanup cap bypass depended on zero incremental admission | A previously paid cleanup could dispatch after its cap was reduced | Exemption requires a stored zero reservation and zero recorded charges; paid cleanup rechecks caps |
| Cleanup retry checked the target's latest eligibility first | Lost local receipt could become unrecoverable after target reconciliation | Recover identical admitted cleanup before new-admission eligibility checks |
| Sparse backend evidence passed the coordinator but failed ledger encoding | Malformed reply could leave dispatching state instead of recording unknown | Reject array holes at the reply boundary and persist unknown |
| Generic monetary normalization changed prototype-named keys and conflated strings with integers | Valid JSON could fail dispatch, or altered payload types could retain authority | Convert only declared monetary fields and preserve ordinary JSON own keys/types |
| Project stop required a previously created scope | A capture-only/future project could not be preemptively stopped | Transactionally create an initially stopped project scope with expected epoch zero; missing resume still fails |
| Digest-named manifest fields accepted placeholder text | Structurally incomplete provenance could appear ready for adapter validation | Require canonical SHA-256 formats while preserving separate source-authenticity checks |

The reviewed coordinator never automatically resubmits unknown actions. A matching acceptance after stop remains recorded as work requiring cleanup. The capture importer preserves missing original configuration, uses source-bound retry identity, and does not register a synthetic run. The exporter derives JSON, digest and Markdown from one synchronous snapshot before I/O; concurrent later changes cannot split the bundle's meaning.

## Verification scope

Tests include real SQLite transactions, real child-process `SIGKILL` at three persistence boundaries, live owner contention, injected reply loss, immutable identity, shared allowance admission, conservative overrun behavior and independent cleanup regressions. Additional tests cover historical capture retries after report/source removal, output consistency and operator commands across separate processes.

All 128 offline tests pass locally. [Linux CI](https://github.com/ronoktanvir/rl-research-harness/actions/runs/41382669902) passed with Node 24 and 25 at `b565c852e8f5bbacb643f4b43a4cb375c86d732f`.

A real CoworkerRL historical report was archived under `historical-main-s11` in the ignored local ledger. It retained producer-reported source references and 30 planned steps while recording missing manifest fields, unknown live execution/allocation/billing and unassessed scientific validity. No CoworkerRL file was modified and no training or provider request occurred in this slice.

These checks establish local behavior under the tested failures. They do not establish remote launch uniqueness, authenticated worker authority, actual cancellation, provider spending ceilings, backup/restore or conference-level scientific quality.
