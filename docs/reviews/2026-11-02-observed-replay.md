# Observed replay adapter: independent reviews

The adapter preserves a useful separation between native replay, authorized observation, numeric credit and scientific judgment. The TypeScript review found and reproduced two inconsistent evidence joins; both are corrected. A subsequent cleanup review found a failure path that could discard a known execution outcome, also corrected. The original 22 independent TypeScript tests and two added cleanup regressions pass, along with `npm run check`. The first sections cover the TypeScript request/result boundaries and local artifact persistence. The separate native-worker and saved-artifact review follows below.

Reviewed files are [observed-replay.ts](../../src/integrations/coworker/observed-replay.ts), [replay-validation.ts](../../src/integrations/coworker/replay-validation.ts), [observed-replay-artifacts.ts](../../src/integrations/coworker/observed-replay-artifacts.ts) and the new routes in [cli.ts](../../src/cli.ts). ## Corrected evidence joins

**Source ownership now constrains the visible sender and private read destination.** The initial validator accepted an authorized message with `sourceBindings[sourceId] = "Alice"` after its visible sender was changed to `"Bob"`. It also accepted the message on a private read page naming Bob. Those records contradicted the supported native witness chain even though their individual field types were valid. The validator now joins a source-bearing message to its named owner and checks the private page’s coworker. Source-null policy and contextual messages do not receive invented ownership. The regression changes these identities while retaining the other bindings, so rejection cannot be explained by a stale outer digest alone.

**Import names now identify their own reviewed files.** Initially, `probing.extraction` could be paired with the catalog module’s path and valid hash. The name and file were independently admissible, but their relationship was false. The validator now checks the Python module name against its module or package path, verifies that path’s registered hash and rejects duplicate imported paths. The regression deliberately supplies another valid manifest entry rather than an arbitrary invalid hash.

## What the 22 independent tests establish

- Request normalization makes detached, frozen snapshots; all selected file, record, root and episode identities affect the digest. It rejects accessors without invoking them, annotation-controlled fields, traversal, invalid primitive types, unsupported source manifests and oversized escaped JSON.
- A completed synthetic result retains every declared required fact, including a fact with no acquisition witness. Missing, duplicate or reordered result rows reject. Repeated legitimate reads preserve one per-fact result; duplicate call identities reject.
- Memo and fact-definition changes must match their digests. Acquisition needs an actual message/read/subsequent-inference chain. A scorer exception stays `null` with an error instead of becoming false. Native terminal validity remains distinct from replay completion; invalid-policy termination cannot carry an invented submitted memo.
- Numeric credit cannot change `semanticEvaluation`, `taskSuccess` or `scientificEvaluation` from `unassessed`. A synthetic denied quotation can therefore retain a positive numeric observation without receiving semantic approval.
- A saved execution can repair missing report/receipt projections and reload after the original source and input directories are deleted. These tests deliberately name a nonexistent Python executable: recovery and loading succeed without a subprocess. Rejected replay remains an incomplete result with null performance counts, rather than a zero-credit successful episode.
- An intent without execution cannot silently rerun. Reload rejects contradictory evidence and edited approval prose even after outer digests are recomputed. Artifact leaves reject symlinks, hard links and duplicate JSON keys.

The synthetic fixtures exercise validation and persistence relationships; they do not demonstrate that an arbitrary fabricated bundle was produced by the native process. Artifact roots and the local controller remain trusted. Hashes detect inconsistency with retained identities, not forgery by a writer able to replace an entire evidence chain.

## Command and temporary-directory review

The new command routes read a bounded request, create a new output directory for execution, print the redacted summary and return a nonzero outcome for incomplete replay. `observed-replay-read` and `observed-replay-recover` use saved evidence without invoking Python. Signal handlers are removed after the run. No material route defect was found in this bounded source review.

The parent now owns a private source-staging directory so timeout or cancellation cannot rely solely on the child’s `finally` block. Initially, an exception from parent `rm` escaped before the known process outcome could be returned and archived. The corrected execution schema records source-staging cleanup as `removed` or `pending`, retaining a pending path separately from the process and replay outcome. A trusted factory dependency permits cleanup fault injection; no request or command-line field selects this behavior.

Two added tests cover this correction. An already-aborted request invokes no Python process; an injected removal exception preserves the cancellation, empty output hashes and pending staging path. A completed synthetic bundle with pending cleanup reloads and recovers without deleting or changing that path. The redacted summary exposes cleanup status. This is source-staging cleanup, not proof of training-worker termination or cloud resource release. Ordinary staged files are read-only beneath owner-writable directories; the tests establish failure handling rather than asserting normal removal fails. A controller crash can still leave source-only staging behind.

## Scientific and operational scope

These are local, private artifact receipts, not ledger registration or experiment authority. Complete native replay establishes the supported reconstruction result; it does not establish historical execution custody, real helper difficulty, semantic validity, task success or learning benefit. Required-fact completeness is checked against the worker’s declared universe here; the native worker must separately derive that universe from the actual instantiated catalog episode.

The TypeScript reviewer ran the 24 regressions and typecheck. The cancellation regression reads the worker template and creates a private temporary directory, but its already-aborted signal prevents process spawning. No provider, service, training or native CoworkeRL execution was performed for that review. Native worker tests and real saved-artifact qualification have separate source-bound records below.

The final reason-code restriction exposed two fixtures using the invented code `native_validation_rejected`. They now use the worker's actual `native_replay_rejected` code, with an added assertion rejecting an unregistered reason. This corrects fixture fidelity without changing semantic labels, failure classification or the 24-test count.

## Independent native-worker and artifact review

A second reviewer ran **22 Python boundary tests**: ten ordinary request/reader/effect-guard tests and twelve explicit opt-in tests using the retained native source and persisted fixtures. The tests are in [coworker_observed_replay_worker_test.py](../../test/integrations/coworker_observed_replay_worker_test.py). No substitute episode or bridge was used. The accepted fixtures retain all ten configured world facts, including native definition metadata and aliases, and both required facts. Their memo, selected-record, source, page and subsequent-inference hashes match the earlier qualification. The original final-read-at-call-cap fixture produces a completed replay with `invalid_policy`, an empty memo and no final-read witness; it does not become task success.

Failure tests cover duplicate or invalid JSONL records, cross-linked identities, judged results, forged ownership, missing or inconsistent separate provenance, unsupported catalog selection, a different world seed, source-byte drift, input hash/size mismatch, links and FIFOs. An ancestor replacement during reading preserves the pinned directory descriptor; a file changed during reading rejects. An oversized projection rejects with a null result instead of truncating evidence. Child-only guard tests deny outside reads, staged writes, socket creation, subprocess creation and environment changes. These tests qualify the reviewed Python boundary, not a general hostile-code isolation mechanism.
