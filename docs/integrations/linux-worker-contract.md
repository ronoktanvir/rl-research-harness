# CoworkeRL supervised Linux worker contract

**CoworkeRL training is not enabled.** The [generic local supervisor](../local-supervisor.md) implements persistent intent, systemd transport, query-only recovery, durable cleanup evidence and a required `Type=notify` deadline gate. The CoworkeRL integration produces an immutable command preview and can separately [verify bounded source/input bytes](coworker-artifact-verification.md). Connecting these components to a training backend still requires immutable deployment, environment/native admission checks and qualification of the complete execution path.

The current generic implementation is source `521ceba91b770b87a3c8a9094425fbcc60b1c3ac`. Native cleanup has [verified Linux evidence](../cleanup-evidence.md). [CI run 41396062992](https://github.com/ronoktanvir/rl-research-harness/actions/runs/41396062992/job/125117528860) also passed the required notification/deadline protocol: seven Linux cases plus their parent, eight passes in 14.465 seconds, including delayed-execution refusal and actual main-PID runtime-extension denial. This is bounded CPU qualification on the tested CI image, not actual CoworkeRL training qualification.

This design follows CoworkeRL HEAD `84b219f64f1152f8b02babea388bfbbfff41e75a`, inspected 2026-11-01; see [the execution audit](coworker-execution-contract.md). No CoworkeRL trainer, credential or provider was exercised. Short CPU service tests have separate [Linux qualification evidence](../systemd-qualification.md).

## Narrow local API and ownership

Start with the dispatcher and systemd manager on the same trusted Linux host. Remote authentication, bounded authorization leases and fencing are separate future work; this local design does not qualify them. An eventual factory should implement the existing `ExperimentBackend` interface with `submit(claim, signal)` and query-only `reconcile(request, signal)`, backed by an injected transport, a durable intent/receipt journal and a trusted profile. No model-facing process may access that journal, the experiment ledger, provider credentials or the manager's control socket.

Resolve an archived plan by digest; verify its action, run and manifest against the claim. Verify immutable source/input/environment bytes and native admission prerequisites, enforce fresh ledger authority, and serialize the action before recording a durable start intent. The generic worker uses `rlh-<hash of workerId and backendKey>.service` as the deterministic unit identity and binds the complete declaration in controller-owned metadata. A worker identity plus unit name forms the stable job ID; a PID or dispatch-attempt UUID does not. Observation also retains machine/boot identity and systemd invocation identity to detect replacement.

The implemented trusted profile fixes the unprivileged user, executable/environment allowlists, read-only roots, writable attempt root, resource ceilings and required deadline-gate interpreter/helper configuration. Training-credential provisioning is not implemented; persisted command/environment declarations must remain nonsecret. Caller-provided systemd properties or shell commands are unsupported. Literal argv uses disabled environment expansion. Fixed service properties include `Type=notify`, initial `NotifyAccess=main`, zero runtime randomization, `Restart=no`, `RuntimeMaxSec`, bounded activation/stop timeouts, `KillMode=control-group`, `SendSIGKILL=yes`, memory/task ceilings and no delegated cgroup.

The trusted gate sends readiness and revokes later notifications, waits for a separate manager barrier, then rechecks time immediately before same-PID trainer execution. The barrier places this check after processing readiness and arming the runtime interval; revocation prevents the trainer's extension requests from being accepted. The helper, interpreter and libraries must be immutable to the trainer and visible through the trusted filesystem profile; `/run/systemd/notify` must remain reachable. Acceptance means the gate reached readiness, not that its final check, trainer admission or training succeeded. The detailed contract is [execution-time deadline enforcement](../execution-deadline.md).

`RuntimeMaxSec` bounds active runtime. Manager queue latency remains unbounded, but the implemented gate refuses a delayed trainer start unless the remaining absolute deadline covers runtime, shutdown grace and the configured safety margin. It uses the later of wall UTC and dispatch UTC advanced by boot time, and rejects a changed boot. A completion-deadline claim still depends on accurate initial time, a shared host clock basis, bounded timer/scheduling/exec/kill delay and no host suspend after activation. The required native margin is at least 1,000 ms; its adequacy is a deployment assumption. Receipts explicitly retain conditional local-host qualification and `absoluteDeadlineEnforced: false`. This time check does not replace current ledger authority or establish a remote revocation lease.

The preview itself checks arithmetic consistency only. Stop revokes new admission, then explicitly requests termination of the owned unit and observes cleanup; losing a local wait is not cancellation. Already submitted provider calls and VM/storage billing may persist after process termination. [Systemd termination semantics](https://www.freedesktop.org/software/systemd/man/latest/systemd.kill.html).

## Crash windows and observation rules

| Durable state / observation | Permitted conclusion and recovery |
|---|---|
| Plan exists, no start intent | No external submission recorded. Fresh authority can admit the next step. |
| Start intent persisted, controller dies before or during submission | Submission may have occurred. Inspect the original deterministic unit; do not automatically start again. |
| Matching unit or durable matching acceptance receipt exists | Worker accepted that job identity. Observe execution separately. |
| Unit absent after an issued intent, manager restart or host reboot | Unknown unless an authoritative receipt resolves it. Absence does not prove nonacceptance. |
| Definitive pre-effect rejection persisted | `not_accepted` may be recorded; any later retry requires explicit ledger requeue/admission. |
| Matching terminal snapshots bracket the exact owned cgroup's empty/absent kernel observation | Record identity-bound cleanup and exit evidence, preserving the manager's actual path field. Evaluation, allocation release and billing settlement remain separate. |

Transient unit names alone cannot supply durable idempotency: systemd can unload unreferenced units and loses transient definitions on reboot. Persist intent before submission and receipts before cleanup; never recycle a unit name as proof a previous job did not run. A crash after intent but before the manager call can therefore leave an unstarted job unknown. This conservative loss of automatic progress is preferable to duplicate paid work. Retaining an exited unit may aid observation, but is not a substitute for the journal. Reconciliation must not start, restart, reset or delete units. [Systemd manager's transient-unit API](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.systemd1.html).

`accepted` means worker acceptance only. A generic command failure, timeout or gate exit code does not establish nonacceptance. Process exit zero does not imply a valid evaluation, and an empty process group does not prove the GPU VM is released. The generic worker supports explicit `cancel` of its own job. Its journal now preserves validated cleanup across cgroup-path removal and reopening; real forced-shutdown evidence yields `failed` for the manager's timeout result rather than inventing cancellation success or cause. Cloud `release`, on-demand checkpoint creation and automatic resume remain unsupported until their separate contracts are implemented.

## Qualification required before enabling execution

Offline preview tests exercise mapping, immutable snapshots, manifest/lineage mismatches, path and limit rejection, and agreement with real ledger action identity. They do not execute the trainer or qualify systemd.

Real Linux CPU fixtures at `0ded185b603fa09064b4ed22885d8c03f2a45c62` have qualified successful/nonzero exits, relative runtime expiry, ignored SIGTERM in a parent and detached child, native cgroup-absence evidence and lost-reply recovery without a second start across journal reopening. Separate offline tests cover controller SIGKILL transaction boundaries and malformed/replacement evidence. These results do not establish host-reboot recovery, every stop-during-start race, remote fencing or artifact collection.

The current notification gate has now passed separate real-manager tests for delayed-start refusal and verified notification-access revocation, including repeated extension attempts from the actual main PID before runtime expiry. Both Node 24 and Node 25 CI jobs also passed 373 offline tests with one intentional native-service skip. The artifact verifier's matching receipt still leaves immutable deployment, environment identity, native tensor fingerprints, checkpoint/resume semantics and scientific preflight pending. Actual CoworkeRL CUDA/vLLM/helper/judge checkpoint-and-resume qualification remains a later, separately bounded experiment. Byte equality and generic service lifecycle evidence cannot substitute for that complete adapter qualification.
