|---|---|---|
| Launch | Refuses a nonempty output directory; creates a fresh random `run_id` in `run-evidence.json` after initial admission checks. | Persist a controller-generated job key before dispatch. The trainer UUID is a later producer identity, not launch idempotency. |
| Status | `report.json` contains step diagnostics; `run-evidence.json` reserves steps before rollouts. | Cancel | The fit loop checks cooperative time/spend boundaries and abort criteria. | Checkpoint | Saves an initial checkpoint and a complete checkpoint after each completed update, before serving reload. | Initially expose `list/inspect latest committed checkpoint`, not on-demand checkpoint creation. ## Resume is already a substantive safety contract

`save_checkpoint` writes adapter tensors, optimizer and RNG state, loop state, identity and a file-hash inventory into a staged directory. It verifies the adapter fingerprint and fsyncs files before publishing. `inspect_checkpoint` checks inventory, checksums, paths, fingerprint and expected identity; restoration checks optimizer layout and loads trainer state with `weights_only=True`. These are native implemented checks, not merely README aspirations. [Publication](/Users/ronoktanvir/CoworkeRL/experiments/coworkerl-v2/src/probing/verl/checkpoint.py:234), [inspection/restoration](/Users/ronoktanvir/CoworkeRL/experiments/coworkerl-v2/src/probing/verl/checkpoint.py:279).

`verify_resume_boundary` requires the originating `run-evidence.json` and matching producer ID. It rejects any reserved step or later artifact at or beyond the checkpoint's next step. An older checkpoint cannot silently erase subsequent attempts. The new process uses a fresh output directory and carries forward elapsed time, GPU estimate and helper/judge counters. Identity binds configuration, source, packages, tokenizer, model, task/scorer/helper provenance and numerical receipt; selected location fields and total `steps` are excluded. Therefore native acceptance of a changed total step count must still pass a new harness manifest/authority decision. [Boundary](/Users/ronoktanvir/CoworkeRL/experiments/coworkerl-v2/src/probing/verl/checkpoint.py:314), [carried state](/Users/ronoktanvir/CoworkeRL/experiments/coworkerl-v2/src/probing/verl/fit_loop.py:1271), [identity exclusions and bindings](/Users/ronoktanvir/CoworkeRL/experiments/coworkerl-v2/src/probing/verl/fit_loop.py:856).

## First controllable adapter and acceptance evidence

Implement a fixed-worker backend before cloud provisioning: one trusted Linux worker supervisor owns a durable job registry and an OS service/process boundary. The broker submits an immutable `launch` request for a frozen, explicitly admitted single-attempt command; it does not give a model arbitrary shell execution or cloud credentials. Bind the harness action key to the worker job ID before spawning, then bind CoworkeRL's generated UUID after it appears. A lost acknowledgement must produce lookup/reconciliation or `unknown`, never a new launch key. Use the existing frozen-plan and qualification verifiers when their scope applies; no alternate harness route should bypass them.

The first implementation can test that supervisor against a purpose-built CPU fixture that emits reports and checkpoint-like artifacts. That qualifies lifecycle mechanics only. CoworkeRL also contains a tiny LoRA/GRPO stand-in smoke, explicitly excluding its distributed/GPU serving path; even that seam requires its declared dependencies and separate compatibility checks. Neither fixture qualifies the actual Qwen/CUDA/vLLM/helper/judge trainer. [Existing smoke scope](/Users/ronoktanvir/CoworkeRL/experiments/coworkerl-v2/src/probing/verl/smoke.py:1).

Required acceptance tests, in order:

1. **Admission and identity:** same launch key/same payload creates one process; changed payload conflicts. Missing source/manifest/qualification identity or exhausted authority prevents spawn. Crash before and after spawn acknowledgement does not duplicate work.
2. **Observation and stop:** restart the controller during a running fixture; recover its job identity and retain exposure. Test PID reuse/worker reboot, stale reports, disconnection, stop during launch, ignored graceful termination and final process-group verification. Lost contact remains unknown.
3. **Artifacts and recovery:** kill the fixture during a write; collect only complete hashed artifacts. Test transfer failure, corrupt inventory, origin-directory retention and refusal to resume from an older checkpoint after later-step reservation. Successful process exit must not imply evaluation approval or allocation release.
4. **Actual trainer qualification, separately authorized:** on the admitted pinned Linux/CUDA/serving stack, run a bounded development attempt with real helper/judge metering, produce a complete checkpoint, resume in a new directory and compare next-update state with a reference. Exercise serving-reload failure, partial-step refusal, stop and independent allocation release. All source/model/data/scorer identities and total compute/API/storage limits must be explicit before this stage.

The source includes tests for canonical checkpoint identities, stochastic checkpoint/resume equivalence, altered/partial checkpoint rejection and instrument binding; they were located but not run during this inspection. Runtime status, current GPU capacity, credential access, current frozen qualification receipts and real deletion behavior remain unverified. The next code slice should build the worker lifecycle fixture and its broker adapter while leaving the actual training capability disabled until that separate evidence exists.
